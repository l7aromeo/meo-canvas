### Added

- An image source can carry its own `httpOptions`, merged over the scene's per
  header name. It works anywhere a URL can appear — an `Image`'s `src`, a
  `backgroundImage` and a `mask` — because the options belong to the source
  rather than to the node. Two sources naming one URL with different headers are
  two requests, not one.
- `canvas.diagnostics` reports markup a render could not use: an unknown tag, a
  value out of range, a value that will not parse. Each `Diagnostic` names the
  `caller`, the `path` as written — the whole of `<weight=1500>`, not `<weight>`
  — and a byte `offset`, so three `<color>` tags in one string can be told
  apart. A diagnostic is not an error; the text still draws.
- `canvas.warnings` and `onImageError` on `Root`. An image that cannot be
  fetched or decoded no longer fails the render: `'placeholder'` (the new
  default) draws a neutral mark at exactly the box the picture would have
  filled, `'ignore'` draws nothing, and `'throw'` is what every earlier version
  did. **All three record the warning** — the choice is what is drawn, never
  what is known.
- Each `ImageWarning` carries the `url`, a `failure` a program can branch on
  (`'status'`, `'host-not-found'`, `'bad-url'`, `'transport'`, `'too-large'`,
  `'other'`), the HTTP `status` where there was one, a readable `detail`, and
  `nodes` — how many nodes asked for that source. Warnings are deduplicated by
  URL, because one dead URL wanted three times is one thing that went wrong.

### Changed

- **Breaking.** A props key a factory does not have is refused, naming it.
  TypeScript's excess property check fires on a fresh object literal and nothing
  else, so props built from a variable, a spread or `JSON.parse` used to carry an
  unknown key through and have it silently ignored. Applies to the container
  factories, `Text`, `Path`, `Image`, the paragraph options and `TextSegment`.
- **Breaking.** A first argument that is not a props object is refused.
  `Box('')`, `Box(42)` and `Box({})` were previously indistinguishable in the
  output: a value with no own keys gave the check nothing to object to, so the
  node was built with defaults and drawn.
- **Breaking.** A font weight outside the range CSS defines is refused. A weight
  in markup that cannot be used is dropped and reported as a diagnostic, rather
  than clamped to the nearest legal one.
- A child may be a `string`, `number` or `bigint` and renders as text, the way
  React does. `null`, `true` and `false` are skipped, so a conditional that does
  not render can be written the obvious way.
- `RichText` accepts bare strings and numbers among its segments, not only
  `TextSegment` objects.
- `BorderStyle` gains `'none'`. A border with no style draws nothing and
  reserves no space.
- A bare node lays out as a browser's `div`.

### Fixed

- A text run's own style now paints. `TextSegment.style` was accepted and its
  colour and decoration were not applied.
- A `data:` URI is read as the bytes it carries rather than as a filename, and a
  URL opened as a filename says so instead of failing obscurely.
- An SVG source is drawn at the size it is drawn at rather than the size it
  declares, and a colour applied to it tints it.
- A picture sits in the content box, where CSS and Chrome put it, and is clipped
  to the element it was placed in.
- A percentage height resolves only against a height layout has settled.
- Letter spacing resolves against the size that declared it, and is no longer
  counted twice — the second half of that arrived with meo-skia-canvas 0.16.
- A hard shadow is offset, so its row is not the same as `none`'s.
- An infinite layout value is bounded rather than dropped.
- A `NaN` is refused where it can be reported and neutralised where it cannot,
  instead of falling into whichever branch was written for extreme input.
- Markup keeps the enclosing colour and weight when one of its values is
  unusable, rather than clearing the paragraph it is in.
- A failed property decode and a rendering failure both name the caller's
  property and the cause.
