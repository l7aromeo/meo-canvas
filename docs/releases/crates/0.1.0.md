The first stable release of `meo-canvas` on crates.io. Describe a picture; get
image bytes back — CSS flexbox, grid and block layout on a Skia backend.

Two prereleases came before it and are indexed at the bottom. Nothing precedes
those: this lineage starts here, so there is no earlier version to cross from
and no migration to describe.

### Added

- **The crate, and the scene contract underneath it.** `Renderer::render` takes
  a tree of nodes and returns a `RenderedCanvas`; encoding is a separate call on
  that, so two formats of one picture cost one layout and one paint. Builders
  and `px(16.0)` rather than object literals, because the scene itself is a flat
  arena a codec can round-trip and a person cannot comfortably write.

- **Layout is CSS, measured against Chrome rather than read from the
  specification.** Flexbox, CSS grid and block, through taffy. Where a question
  has a CSS answer, the answer is what a browser does — `z-index` follows CSS's
  rule for positioned, flex and grid children rather than a narrower one, and
  `LayoutStyle::default()` is CSS's `Display::Block` so a bare `Node` behaves
  like a bare `<div>`.

- **Text is shaped and broken here rather than handed to a canvas.** Lines are
  measured and broken in `crate::lines`, which is what makes a paragraph behave
  like a browser's; a canvas has no paragraph. A measured leaf reports its
  baseline from its border box, because that is where CSS measures a flex item's
  baseline from.

- **Nodes**: containers, text, rich text, images, paths, grids, charts and
  masks, with gradients, shadows, borders, transforms and blend modes on the one
  flat `Style`. Every property is reachable by literal — `Style` is public and
  deliberately not `#[non_exhaustive]`.

- **Pages, and animation without a clock.** A `Scene` carries one or more page
  trees, already built. Several pages become frames in gif, apng, webp and avif,
  sheets in pdf and tiff, and sizes in ico. Nothing in the core calls back to
  produce a page, so an animated render needs no retained state and no re-entry
  into caller code.

- **A page as tall as its content.** `Scene::content_height` makes `size.height`
  a floor rather than the height, so "at least this tall" is expressible without
  a second flag.

- **Twelve encodings**: png, jpg, webp, avif, tiff, bmp, ico, svg, pdf, gif,
  apng and raw bytes.

- **Diagnostics are a channel rather than an error.** A value the renderer could
  not use does not fail the render: `into_scene` returns the scene and a
  `Vec<Diagnostic>` beside it, each naming the path it is about — the markup tag
  as written, value included — and the byte offset that tells three `<color>`
  tags in one string apart.

- **Four crates publish together**: `meo-canvas` is the authoring surface,
  `meo-canvas-core` runs resolve, measure, layout, paint and encode,
  `meo-canvas-scene` is the dependency-free scene contract and its byte codec,
  and `meo-canvas-cli` reads a scene from disk or a pipe.

- **Two optional features and one rule that does not bend.** `metal` and
  `vulkan` select a GPU backend, neither on by default, so a plain build renders
  on the CPU and `cargo check` stays portable. `net` puts URL fetching behind a
  flag — without it an `ImageSource::Url` is `Error::UnresolvedSource` and no
  HTTP stack is linked. **No async runtime enters the tree**, and `just
runtime-free` fails if one does.

- **Minimum supported Rust version 1.98.**

### Known limitations

**Some behaviour here is compensation for the layout engine underneath rather
than a fix in it**, and it is marked as such in the source. Each compensation
carries a probe pinned to what taffy does today, which fails on the day taffy
stops needing it — so that behaviour can move again, toward the browser. The
issues this repository filed stay open until it does.

**Four are open at this release**, each because the defect is taffy's and the
repair here is narrower than a fix:
[`#97`](https://github.com/l7aromeo/meo-canvas/issues/97),
[`#104`](https://github.com/l7aromeo/meo-canvas/issues/104),
[`#107`](https://github.com/l7aromeo/meo-canvas/issues/107) and
[`#123`](https://github.com/l7aromeo/meo-canvas/issues/123). Each names the
shape it does not cover.

**One shape is deliberately not compensated**: a flex item stretched across its
line and then asked for a main size from that stretch comes out `424 x 248`
where a browser gives `424 x 424` — which overflows its own line. Producing an
overflowing box is a layout change nobody asked for, and the upstream proposal
to make it taffy's own answer is open rather than merged.
