### Fixed

- **A bar's value label is written as given rather than rounded to two
  decimals.** It went through the y-axis default formatter, where rounding is
  deliberate and the npm surface rounds with it — so the helper was right and
  only this caller was wrong. A bar of `2.345` was labelled `2.35`, a number
  the caller never gave.

  One spelling difference remains and this release does not close it:
  JavaScript switches to exponential notation at `1e21` and Rust's `Display`
  never does, so a value of `1e21` is `1e+21` on the npm surface and
  `1000000000000000000000` here. The y-axis path parts one decade later,
  at `1e22`, because rounding `1e21` to two decimals lands a fraction below it
  and both languages then write that out in full. Both boundaries are pinned by
  `crates/meo-canvas/tests/chart_number_spelling.rs` and named at the two call
  sites, so the deviation is checked rather than merely known.

- **A pie or doughnut slice label carries the chart's font family.** It built
  its text inline instead of going through the helper every other piece of
  chart text uses, so a chart drawn in a stated family rendered its slice
  labels in the default one.

- **A doughnut is named for its kind rather than for the size of its hole.**
  `inner_fraction: Some(0.0)` produced a node called `pie chart`: the size of
  the hole and the kind of chart were one fact, and a caller who asked for a
  doughnut got one whose node said otherwise. The name is encoded, so this was
  a difference in the bytes rather than a label.

- **A colour string this crate cannot parse is refused rather than drawn in
  black.** Six sites resolved a caller's colour with a silent fallback. A chart
  colour is the only place on this surface where a style arrives as a `String`
  rather than as a typed value, which makes these builders a writer in the
  sense `AGENTS.md` uses — the writer refuses what the type forbids — and the
  npm surface already refuses the same input.

  **This changes behaviour for existing callers.** Code that passes a colour
  this crate cannot parse renders today, in black, and will now fail to build
  the chart with `Error::Chart` naming which colour role failed. That is the
  point of the change rather than a side effect, and it makes the two surfaces
  answer the same input the same way, but it is a visible difference for
  anyone relying on the old silence.

  An absent colour is not an unreadable one and still takes the default.

- **An animated AVIF is read in the colour its container states**, with
  `meo-skia-canvas` 0.16.3. An animation carries its colour description inside
  the sample entry in `stsd` rather than among its item properties, and nothing
  descended that far, so such a file was decoded by its bitstream. Precedence
  is now shared with the still path and the colour is read per track.

### Changed

- **`rustls` is required at `0.23.45` or newer** under the optional `net`
  feature, closing `RUSTSEC-2026-0285` — TLS 1.3 handshake messages accepted
  across encryption-level boundaries, rated medium. `ureq` requires `^0.23`,
  which resolves to the affected `0.23.44`, so a consumer of this crate could
  reach it even though this repository's own lockfile could not. Nothing here
  imports `rustls`; the requirement exists to raise that floor and is removed
  when `ureq` raises its own. `ureq` moves to 3.4.2 with it.
