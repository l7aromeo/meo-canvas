### Added

- **Breaking.** `Scene` is `#[non_exhaustive]`, so a field added later is not a breaking change, and it gains `Scene::fetched_images`: the bodies of fetches the caller made before rendering, each a `FetchedImage` with the URL and `HttpOptions` of the request that returned it. A `Url` source whose URL and options match one takes its body rather than being fetched, with or without `net`, and a body that will not decode softens under `on_image_error` as one the renderer fetched does, where the same bytes as `ImageSource::Bytes` fail the render. The npm package fills it for every image it fetches (`l7aromeo/meo-canvas#240`). Outside `meo-canvas-scene` a `Scene` can no longer be written as a struct expression, `..Scene::new(size)` included: call `Scene::new(size)` and set the public fields on the result.
- Under `net`, `Root::image_cache` keeps fetched images across renders, so a server drawing many pictures from the same images fetches each once rather than per render. `ImageCache::new(store)`, with `fallback_ttl` and `stale_if_error`, takes a `MemoryStore`, a `DiskStore` or an `ImageStore` of your own, in `meo_canvas::image_cache`. It follows HTTP caching as Chrome does, down to how it reads dates and merges a `304` into the stored response (`http-cache.tsv`): a fresh image is drawn with no request, an expired one is revalidated with its `ETag` or `Last-Modified`, `no-store` is not kept and `no-cache` revalidates every time, and when revalidating fails with a transport error, a timeout or a 5xx the expired copy is drawn for up to 24 hours past expiry, or the response's own `stale-if-error`, with a diagnostic. Renders on several threads requesting one image share one fetch. A store that fails never fails a render: the image is fetched and the failure is on `Canvas::diagnostics`. The disk store's files are the npm package's too, so a Rust process and a Node process can share a directory. `meo-canvas-core` has the same as `Renderer::render_with_cache` and `Resolved::with_cache`. Without a cache nothing changes (`l7aromeo/meo-canvas#239`).

### Changed

- The scene file format is version 11, which carries `fetched_images`. `codec::decode` still reads version 10, so a `.mcs` file written by 0.2.x loads as it did, with no fetched images; `codec::encode` writes 11, which 0.2.x refuses. Any other version is refused with `CodecError::UnsupportedVersion` ("scene format version 9, expected 10 or 11"), which carries the oldest version read as `oldest`.
- **Breaking.** `meo_canvas_core::lines::RunStyle` gains a public field, `trimmed`, which says a run is one full-width punctuation mark set at half its em with the face's `halt`, and `RunStyle`, `Run`, `Line` and `Block` in `meo_canvas_core::lines` are `#[non_exhaustive]`, so a field added later is not a break. Code outside the crate can no longer build them with a struct literal: take a `RunStyle` from `RunStyle::of` or `RunStyle::base` and set its fields, and take `Run`, `Line` and `Block` from `wrap` and `layout`, which make them. `RunStyle::family` is an `Arc<str>` rather than a `String`, so a run's style is cloned without copying its family name: read it as `&*run.style.family`, or call `.to_string()` for an owned copy, and set it with `"Family".into()`. The `meo-canvas` crate's own API is unchanged.

### Fixed

- Text with no spaces wraps where Chrome wraps it rather than running off the line. A line broke only at a space, so Chinese, Japanese, Korean or Thai written without spaces was one unbreakable word: `"漢字".repeat(20)` at 16px in a 200px box drew one line where Chrome draws four. Lines now break where Chrome's breaker allows: between ideographs and kana, between an ideograph and a Latin word but not inside the word, never before `、`, `。`, `」` or `）` and never after `「` or `（`, before small kana and `ー` as Chrome's `line-break: auto` allows, and inside Thai by dictionary. A text node's min-content width, which a flex item shrinks to, is its widest unbreakable piece, one ideograph for a run of them. Kerning across a break is kept, so a line of katakana fits as many characters as Chrome's (`line-break.tsv`, `l7aromeo/meo-canvas#237`).
- Latin text breaks where Chrome breaks it too, which moves some lines: after a hyphen, so `well-known` can end a line at `well-`; after `?`; and before an opening bracket that follows punctuation, as in `a.(b)`. `x86-64` breaks after its hyphen and `-5` does not. A no-break space no longer breaks a line, and a word whose style changes partway, such as `<b>bold</b>face` in markup, no longer breaks where it changes.
- An ideographic space, U+3000, and the other Unicode spaces besides the space, the tab and the no-break space are measured in their font, as Chrome sets them: an ideographic space at 16px is 16px wide, where it was drawn as a word gap of a few pixels, and one that begins a paragraph, as a Japanese indent does, is drawn rather than dropped.
- A line keeps text that overfills it by up to a 64th of a pixel, as Chrome's does: Chrome lets a line run one of its layout units past the box. On Linux, where FreeType makes a 16px ideograph from a 1000-unit font 16.0000305px wide, six of them in a 96px box drew five to a line where Chrome draws six, and a line Chrome fills to that last 64th, such as `漢字漢字漢字、」漢字` in 111.99px, broke a character early because the excess pushed it past (`l7aromeo/meo-skia-canvas#695`).
- `HttpOptions::canonical` trims spaces and tabs around a header's value, as the npm package's `Headers` does, so a source whose header value has them encodes to the same scene bytes on both surfaces and is sent as HTTP defines the value (`l7aromeo/meo-canvas#239`).
- Full-width punctuation is narrowed where Chrome's default `text-spacing-trim: normal` narrows it, in a face with the OpenType `halt` feature. Of two marks side by side, an opening bracket or quote loses the empty half of its em, and otherwise a closing one or a comma, stop or colon does, so `漢字、。」漢字` at 16px is 96px wide rather than 112; a middle dot or an ideographic space narrows its neighbour and never itself. A closing bracket or quote at the end of a line loses its half where that lets the line fit, so `漢字漢字漢字」` fits a 104px line. At the start of a line an opening bracket is set whole, while a closing mark narrowed by the one after it stays narrowed; nothing is narrowed in a face without `halt`. Lines, min-content widths and truncation all follow, and the narrowed marks are drawn with `halt` (`text-spacing-trim.tsv`, `l7aromeo/meo-canvas#242`).
