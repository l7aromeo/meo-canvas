### Fixed

- **A decoded image keeps the colour space its file states.** An AVIF tagged
  through its `colr` box or through its own AV1 bitstream, and a BMP carrying a
  `BITMAPV4HEADER`, were all read as sRGB, so anything outside sRGB was clipped
  on the way in. A Display P3 red stored as `234,51,35` now reads back
  `255,0,0`.

- **A second `to_buffer` of one `RenderedCanvas` is no longer served the first
  export's colour conversion.** Asking for sRGB and then for a wider space
  returned the sRGB rasterisation both times, with everything the first
  conversion clipped still clipped. Only that order was affected; the reverse
  was always correct.

  Both arrive with `meo-skia-canvas` 0.16.2 and are measured by that project
  rather than here. Nothing in this crate changed, and no golden moved.

- **`rustls` moves to 0.23.45**, closing `RUSTSEC-2026-0285` — TLS 1.3
  handshake messages accepted across encryption-level boundaries, rated
  medium. It reaches this crate only with the `net` feature, which is not
  default.
